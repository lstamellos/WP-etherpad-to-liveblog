# Διαχείριση λειτουργικής έκδοσης 0.3.1

**Πριν από παραγωγή:** η σύνδεση και η χειροκίνητη δημοσίευση μέσω POSTOK έχουν επιβεβαιωθεί στο δοκιμαστικό Liveblog OmniaTV. Η νέα αυτοματοποίηση μέσω native polling / WP-Cron και οι διορθώσεις δημοσιευμένων εγγραφών απαιτούν πρόσθετη δοκιμή.

## Προϋποθέσεις

1. Ενεργό Automattic Liveblog στο WordPress και δικαιώματα editor/publisher.
2. Μη δημόσια επεξεργάσιμο Etherpad. Κάθε χρήστης με δικαίωμα εγγραφής μπορεί να ενεργοποιήσει POSTOK· **μη συνδέετε δημόσιο pad χωρίς έλεγχο πρόσβασης**.
3. Πρόσβαση του WordPress server στα δημόσια HTTPS endpoints `/p/<padID>/export/txt` και `/p/<padID>/export/etherpad`, χωρίς API credentials.
4. Ενεργό WP-Cron για συμπληρωματικό συγχρονισμό, εφόσον δεν υπάρχει αναγνώστης στο Liveblog. Δεν απαιτείται systemd service.

Για **νέες συνδέσεις** δεν απαιτείται καμία ρύθμιση στο `wp-config.php`: εισάγεται το πλήρες URL δημόσια αναγνώσιμου pad, από οποιοδήποτε HTTPS Etherpad instance. Το plugin δεν στέλνει credentials στο Etherpad.

Σε περίπτωση Cloudflare Challenge, η εξαίρεση πρέπει να αφορά τη δημόσια IP του WordPress server και **μόνο** τα συγκεκριμένα export endpoints (`/p/<padID>/export/txt` και `/p/<padID>/export/etherpad`). Η προηγούμενη εξαίρεση `/api` δεν καλύπτει τις εξαγωγές.

Οι παλιές, ήδη αποθηκευμένες συνδέσεις χωρίς `origin` διατηρούν τον προηγούμενο API client και τυχόν υπάρχουσα αυθεντικοποίηση. Η πρώτη σύνδεση κάνει baseline χωρίς αναδρομική δημοσίευση.

## Σύνδεση

Στο post με ενεργοποιημένο Liveblog εμφανίζεται το meta box **Etherpad → Liveblog**. Εισάγουμε URL `/p/<padID>`, βεβαιώνουμε περιορισμένη εγγραφή και επιλέγουμε **Connect pad**. Στην 0.2.1 το αίτημα υποβάλλεται μέσω WordPress AJAX και **δεν** αποθηκεύεται από το γενικό κουμπί «Ενημέρωση» του post. Μετά την επιτυχία το πλαίσιο πρέπει να εμφανίζει το pad, `Status: active` και revision· σε σφάλμα εμφανίζεται μήνυμα. Αν παραμείνει «Connect pad», ελέγξτε το Network tab του browser για `admin-ajax.php`, `wp_ajax_wpelb_action`, 403 nonce ή 400 API error. Τα προϋπάρχοντα POSTOK **δεν αναδημοσιεύονται**. `Pause` σταματά νέο συγχρονισμό, `Resume` επαναφέρει. `Disconnect` διατηρεί όλες τις δημοσιευμένες ενημερώσεις αλλά διαγράφει την αντιστοίχιση και δεν επιτρέπεται όταν εκκρεμεί αβέβαιη εγγραφή.

## Αυτόματος συγχρονισμός χωρίς systemd

Η έκδοση 0.3.1 αξιοποιεί το native polling του Liveblog. Κάθε αίτημα GET στη διαδρομή `/wp-json/liveblog/v1/<post_id>/entries/<start>/<end>/` που φτάνει στο WordPress μπορεί να ενεργοποιήσει έναν συγχρονισμό μετά την παραγωγή της απόκρισης. Ο έλεγχος περιορίζεται σε **έναν ανά 5 δευτερόλεπτα ανά συνδεδεμένο post** (DB-backed atomic throttle), ανεξάρτητα από τον αριθμό αναγνωστών.

Με PHP-FPM, η απόκριση ολοκληρώνεται μέσω `fastcgi_finish_request()` πριν την ανάγνωση του Etherpad, άρα ο συγχρονισμός δεν προσθέτει χρόνο αναμονής στο polling των αναγνωστών. Χωρίς PHP-FPM, η εργασία προγραμματίζεται μέσω WP-Cron.

Παράλληλα, το ίδιο plugin προγραμματίζει WP-Cron κάθε **60 δευτερόλεπτα** για όλα τα ενεργά συνδεδεμένα pads. Το WP-Cron δεν εγγυάται ακριβές χρονικό διάστημα: ενεργοποιείται όταν υπάρχει αίτημα προς το WordPress που φτάνει στην PHP. Cache Cloudflare ή `DISABLE_WP_CRON` μπορούν να αναβάλουν το fallback. Το ίδιο ισχύει για το polling όταν δεν υπάρχουν αναγνώστες.

Οι δύο μηχανισμοί καλούν τον *ίδιο* ασφαλή synchronizer, με κλείδωμα ανά post, προστασία από διπλή δημοσίευση και έλεγχο παλιών POSTOK. Δεν απαιτείται ξεχωριστός daemon.

Για διαγνωστική χειροκίνητη εκτέλεση:

```bash
wp etherpad-liveblog run --once
```

Επαλήθευση του cron:

```bash
wp cron event list --hook=wpelb_periodic_sync
```

Οι προϋπάρχουσες δημοσιεύσεις δεν επανεκτελούνται. Για απαιτήσεις απόλυτα σταθερής καθυστέρησης ανεξάρτητα από επισκεψιμότητα απαιτείται εξωτερικός χρονοπρογραμματιστής ή webhook στο Etherpad.

## Ασφάλεια/σφάλματα

- **Pending operation:** έγινε ή επιχειρήθηκε μια αβέβαιη εγγραφή. Ο συγχρονισμός παγώνει για αποφυγή διπλής δημοσίευσης. Απαιτείται χειροκίνητη επαλήθευση του αντίστοιχου original Liveblog ID πριν τη συνέχιση — δεν υπάρχει ακόμη UI αυτόματου reconciliation.
- **Conflict:** κάποιος άλλαξε το ίδιο entry απευθείας στο WordPress. Το συγκεκριμένο block παύει να ενημερώνεται αυτόματα, όχι τα υπόλοιπα.
- **Marker ambiguity:** μεταφέρθηκε/διαγράφηκε/τροποποιήθηκε ήδη δημοσιευμένο `POSTOK`· διακόπτεται ο συγχρονισμός της σύνδεσης, χωρίς επαναχαρτογράφηση κατά προσέγγιση.
- **Revision history reset/gap >500:** pause· απαιτείται έλεγχος. Δεν γίνεται αυτομάτως αρχικοποίηση που θα διέγραφε τα mappings.
- **Κλείσιμο/αρχειοθέτηση Liveblog:** παύση νέων εγγραφών.
- **Χειροκίνητο κλείδωμα:** αν πεθάνει η διεργασία την ώρα του συγχρονισμού, μπορεί να παραμείνει `wpelb_lock_<postid>` στο WP options. Πρώτα βεβαιωθείτε ότι δεν εκτελείται worker για το post, κατόπιν διαγράψτε το συγκεκριμένο option. Μην αφαιρείτε κλειδώματα στα τυφλά.

## Όρια MVP

Plain text (παράγραφοι, αλλαγές γραμμής), όχι rich text Etherpad. Το δημόσιο archive διατηρεί ολόκληρο το ιστορικό και έχει όριο 8 MiB· μεγάλες ή ασυνεπείς εξαγωγές απαιτούν έλεγχο. Meta box σε posts, όχι ακόμη σε custom post types. Οι νέες δημοσιεύσεις εμφανίζονται στον επόμενο κύκλο και οι διορθώσεις όταν παρέλθουν 5 δευτερόλεπτα από την τελευταία παρατηρημένη αλλαγή **στο συγκεκριμένο block**.

Καμία αυτόματη ενέργεια δεν πρέπει να πραγματοποιηθεί στα παραγωγικά pads πριν τη δοκιμή και τη ρητή σύνδεση από εξουσιοδοτημένο editor.
