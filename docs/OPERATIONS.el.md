# Οδηγός λειτουργίας — WP Etherpad to Liveblog

**Πεδίο εφαρμογής:** Ο οδηγός ισχύει για οποιονδήποτε ιστότοπο WordPress με το Automattic Liveblog και οποιοδήποτε δημόσια αναγνώσιμο HTTPS Etherpad. Όλα τα ονόματα host, οι διαδρομές, οι χρήστες και τα μυστικά πρέπει να αντικαθίστανται με τα στοιχεία της συγκεκριμένης εγκατάστασης. Για τη γρήγορη εγκατάσταση, βλ. [README](../README.md).

## Έκδοση 0.5.0: POSTOK, NOPOST και επιλογή συντάκτη

Οι εντολές αναγνωρίζονται **μόνο όταν αποτελούν ολόκληρη γραμμή**. Δεκτές μορφές (με οποιονδήποτε συνδυασμό πεζών/κεφαλαίων και ελληνικών/λατινικών χαρακτήρων):

- **Δημοσίευση:** `POSTOK`, `postok`, `ΠΟΣΤΟΚ`, `ποστοκ`.
- **Παράλειψη:** `NOPOST`, `nopost`, `ΝΟΠΟΣΤ`, `νοποστ`.

Το `POSTOK` δημοσιεύει το προηγούμενο πλήρες τμήμα ως μία ενημέρωση. Το `NOPOST` **κλείνει και απορρίπτει το προηγούμενο τμήμα** χωρίς να δημιουργεί δημοσίευση. Οι παλιές εντολές `NOPUB`/`ENDNOPUB` εξακολουθούν να ισχύουν για συμβατότητα, αλλά έχουν διαφορετική λειτουργία (απόκρυψη ενσωματωμένης περιοχής).

**Προσοχή:** Δεν ξαναγράφουμε ή αντικαθιστούμε παλιούς δείκτες `POSTOK`, ακόμη κι αν θέλουμε να αλλάξουμε πληκτρολόγιο. Ο μηχανισμός παρακολουθεί τις θέσεις τους σε κάθε revision και προστατεύει από εσφαλμένη αντιστοίχιση εγγραφών.

Στο πλαίσιο **Etherpad → Liveblog** του WordPress, εμφανίζεται πεδίο αναζήτησης με όνομα ή username και επιλογή `Author for new pad updates`. Επιλέγουμε τον επιθυμητό WordPress χρήστη και:

- Κατά τη νέα σύνδεση επιλέγουμε **Connect pad**.
- Για υπάρχουσα σύνδεση επιλέγουμε **Save author**. Η αλλαγή ισχύει **μόνο για τις επόμενες νέες δημοσιεύσεις**, όχι αναδρομικά.
- Ο επιλεγμένος συντάκτης χρειάζεται το δικαίωμα `edit_posts`. Ο χρήστης που αρχικά συνέδεσε το pad παραμένει ξεχωριστά καταγεγραμμένος ως εξουσιοδοτημένος publisher. Δεν απονέμονται νέα δικαιώματα.

Για δοκιμή σε υπάρχον test pad: προσθέτουμε νέο τμήμα με `νοποστ` και ελέγχουμε ότι **δεν εμφανίζεται** στο Liveblog, και κατόπιν νέο τμήμα με `ποστοκ` και ελέγχουμε ότι εμφανίζεται με τον επιλεγμένο author. Οι ήδη δημοσιευμένες ενημερώσεις διατηρούν τα παλιά IDs και authors.

## Προϋποθέσεις

1. Ενεργό Automattic Liveblog στο WordPress και δικαιώματα editor/publisher.
2. Μη δημόσια επεξεργάσιμο Etherpad. Κάθε χρήστης με δικαίωμα εγγραφής μπορεί να ενεργοποιήσει POSTOK· **μη συνδέετε δημόσιο pad χωρίς έλεγχο πρόσβασης**.
3. Πρόσβαση του WordPress server στα δημόσια HTTPS endpoints `/p/<padID>/export/txt` και `/p/<padID>/export/etherpad`, χωρίς API credentials.
4. Ενεργό WP-Cron για συμπληρωματικό συγχρονισμό, εφόσον δεν υπάρχει αναγνώστης στο Liveblog. Δεν απαιτείται systemd service.

Για **νέες συνδέσεις** δεν απαιτείται καμία ρύθμιση στο `wp-config.php`: εισάγεται το πλήρες URL δημόσια αναγνώσιμου pad, από οποιοδήποτε HTTPS Etherpad instance. Το plugin δεν στέλνει credentials στο Etherpad.

Σε περίπτωση challenge από Cloudflare ή άλλο WAF, η εξαίρεση πρέπει να αφορά τη δημόσια IP του WordPress server και **μόνο** τα συγκεκριμένα export endpoints (`/p/<padID>/export/txt` και `/p/<padID>/export/etherpad`). Η προηγούμενη εξαίρεση `/api` δεν καλύπτει τις εξαγωγές.

Οι παλιές, ήδη αποθηκευμένες συνδέσεις χωρίς `origin` διατηρούν τον προηγούμενο API client και την αυθεντικοποίησή του, **αλλά απαιτούν ρητό** `WPELB_ETHERPAD_BASE_URL` στο `wp-config.php`. Δεν υπάρχει προκαθορισμένος Etherpad host. Οι νέες συνδέσεις μέσω public exports δεν χρειάζονται καμία από αυτές τις ρυθμίσεις. Η πρώτη σύνδεση κάνει baseline χωρίς αναδρομική δημοσίευση.

## Σύνδεση

Στο post με ενεργοποιημένο Liveblog εμφανίζεται το meta box **Etherpad → Liveblog**. Εισάγουμε URL `/p/<padID>`, βεβαιώνουμε περιορισμένη εγγραφή και επιλέγουμε **Connect pad**. Στην 0.2.1 το αίτημα υποβάλλεται μέσω WordPress AJAX και **δεν** αποθηκεύεται από το γενικό κουμπί «Ενημέρωση» του post. Μετά την επιτυχία το πλαίσιο πρέπει να εμφανίζει το pad, `Status: active` και revision· σε σφάλμα εμφανίζεται μήνυμα. Αν παραμείνει «Connect pad», ελέγξτε το Network tab του browser για `admin-ajax.php`, `wp_ajax_wpelb_action`, 403 nonce ή 400 API error. Τα προϋπάρχοντα POSTOK **δεν αναδημοσιεύονται**. `Pause` σταματά νέο συγχρονισμό, `Resume` επαναφέρει. `Disconnect` διατηρεί όλες τις δημοσιευμένες ενημερώσεις αλλά διαγράφει την αντιστοίχιση και δεν επιτρέπεται όταν εκκρεμεί αβέβαιη εγγραφή.

## Άμεση ενημέρωση μέσω υπογεγραμμένου Etherpad webhook

Στην έκδοση 0.4.0 προστέθηκε το `POST /wp-json/wpelb/v1/notify`. Κάθε ειδοποίηση περιλαμβάνει μόνο `origin`, `pad_id`, `revision` και δύο HTTP headers (timestamp, event ID), μαζί με υπογραφή HMAC-SHA256. Το WordPress επιτρέπει μόνο υπάρχουσες ενεργές αντιστοιχίσεις (origin+pad ID) και καλεί τον ήδη υπάρχοντα synchronizer· το εξωτερικό payload **δεν** επιλέγει WordPress post.

Για δημιουργία μυστικού τοπικά:

```bash
openssl rand -hex 32
```

Στο `wp-config.php`:

```php
define( 'WPELB_WEBHOOK_SECRET', 'ΤΟ_ΙΔΙΟ_ΜΥΣΤΙΚΟ_ΚΑΙ_ΣΤΟ_ETHERPAD' );
```

Το προαιρετικό Etherpad plugin `ep_liveblog_webhook` εγκαθίσταται **στο Etherpad**, έχει δικό του repository και χρησιμοποιεί το ίδιο μυστικό (προτιμότερα μέσω `EP_LIVEBLOG_WEBHOOK_SECRET` στο περιβάλλον διεργασίας). Ρυθμίζουμε `origin`, `endpoint` και περιορισμό σε συγκεκριμένα `padIds` ή `padPrefix`. Δεν στέλνονται περιεχόμενα των pads. Το Etherpad στέλνει δεύτερη ειδοποίηση μετά ~7,5 δευτερόλεπτα αδράνειας, για να ολοκληρωθεί ο 5-second edit debounce ακόμη και χωρίς αναγνώστες.

Ελέγχουμε τα γεγονότα/αρχεία καταγραφής του αντίστοιχου WAF για ενδεχόμενο challenge στο POST `/wp-json/wpelb/v1/notify`. Η εξαίρεση, αν χρειαστεί, περιορίζεται στο POST από τη γνωστή IP του Etherpad server προς αυτή τη διαδρομή.

## Ανεξάρτητος system cron — εφεδρικός έλεγχος ανά λεπτό

Επειδή το native polling και το WP-Cron εξαρτώνται από επισκεψιμότητα, προσθέτουμε cron στον server WordPress μέσω `crontab -e` ή του διαχειριστή εργασιών της φιλοξενίας, **ως τον κατάλληλο OS user**, μία φορά κάθε λεπτό:

```crontab
* * * * * flock -n /HOME/ACCOUNT/.wpelb-cron.lock /ABSOLUTE/PATH/TO/wp --path=/ABSOLUTE/PATH/TO/WORDPRESS etherpad-liveblog run --once
```

Αντικαθιστούμε τις διαδρομές με τις πραγματικές. Δεν απαιτείται systemd ή μόνιμη PHP διεργασία. Το cron καλύπτει εξωτερικά Etherpad instances, απώλεια webhook, μεμονωμένη αποτυχία δικτύου, απουσία επισκεπτών και επανεκκίνηση υπηρεσιών. Η ειδοποίηση webhook δεν επιβεβαιώνει μόνη της δημοσίευση: το HTTP 202 δηλώνει μόνο αποδοχή του trigger.

## Αυτόματος συγχρονισμός χωρίς systemd

Η έκδοση 0.3.1 αξιοποιεί το native polling του Liveblog. Κάθε αίτημα GET στη διαδρομή `/wp-json/liveblog/v1/<post_id>/entries/<start>/<end>/` που φτάνει στο WordPress μπορεί να ενεργοποιήσει έναν συγχρονισμό μετά την παραγωγή της απόκρισης. Ο έλεγχος περιορίζεται σε **έναν ανά 5 δευτερόλεπτα ανά συνδεδεμένο post** (DB-backed atomic throttle), ανεξάρτητα από τον αριθμό αναγνωστών.

Με PHP-FPM, η απόκριση ολοκληρώνεται μέσω `fastcgi_finish_request()` πριν την ανάγνωση του Etherpad, άρα ο συγχρονισμός δεν προσθέτει χρόνο αναμονής στο polling των αναγνωστών. Χωρίς PHP-FPM, η εργασία προγραμματίζεται μέσω WP-Cron.

Παράλληλα, το ίδιο plugin προγραμματίζει WP-Cron κάθε **60 δευτερόλεπτα** για όλα τα ενεργά συνδεδεμένα pads. Το WP-Cron δεν εγγυάται ακριβές χρονικό διάστημα: ενεργοποιείται όταν υπάρχει αίτημα προς το WordPress που φτάνει στην PHP. Cache Cloudflare ή `DISABLE_WP_CRON` μπορούν να αναβάλουν το fallback. Το ίδιο ισχύει για το polling όταν δεν υπάρχουν αναγνώστες.

Οι δύο μηχανισμοί καλούν τον *ίδιο* ασφαλή synchronizer, με κλείδωμα ανά post, προστασία από διπλή δημοσίευση και έλεγχο παλιών POSTOK. Δεν απαιτείται ξεχωριστός daemon.

Για διαγνωστική χειροκίνητη εκτέλεση:

```bash
wp etherpad-liveblog run --once
```

Επαλήθευση του cron:

```bash
wp cron event list --hook=wpelb_periodic_sync
```

Οι προϋπάρχουσες δημοσιεύσεις δεν επανεκτελούνται. Για απαιτήσεις απόλυτα σταθερής καθυστέρησης ανεξάρτητα από επισκεψιμότητα απαιτείται εξωτερικός χρονοπρογραμματιστής ή webhook στο Etherpad.

## Ασφάλεια/σφάλματα

- **Pending operation:** έγινε ή επιχειρήθηκε μια αβέβαιη εγγραφή. Ο συγχρονισμός παγώνει για αποφυγή διπλής δημοσίευσης. Απαιτείται χειροκίνητη επαλήθευση του αντίστοιχου original Liveblog ID πριν τη συνέχιση — δεν υπάρχει ακόμη UI αυτόματου reconciliation.
- **Conflict:** κάποιος άλλαξε το ίδιο entry απευθείας στο WordPress. Το συγκεκριμένο block παύει να ενημερώνεται αυτόματα, όχι τα υπόλοιπα.
- **Marker ambiguity:** μεταφέρθηκε/διαγράφηκε/τροποποιήθηκε ήδη δημοσιευμένο `POSTOK`· διακόπτεται ο συγχρονισμός της σύνδεσης, χωρίς επαναχαρτογράφηση κατά προσέγγιση.
- **Revision history reset/gap >500:** pause· απαιτείται έλεγχος. Δεν γίνεται αυτομάτως αρχικοποίηση που θα διέγραφε τα mappings.
- **Κλείσιμο/αρχειοθέτηση Liveblog:** παύση νέων εγγραφών.
- **Χειροκίνητο κλείδωμα:** αν πεθάνει η διεργασία την ώρα του συγχρονισμού, μπορεί να παραμείνει `wpelb_lock_<postid>` στο WP options. Πρώτα βεβαιωθείτε ότι δεν εκτελείται worker για το post, κατόπιν διαγράψτε το συγκεκριμένο option. Μην αφαιρείτε κλειδώματα στα τυφλά.

## Όρια MVP

Plain text (παράγραφοι, αλλαγές γραμμής), όχι rich text Etherpad. Το δημόσιο archive διατηρεί ολόκληρο το ιστορικό και έχει όριο 8 MiB· μεγάλες ή ασυνεπείς εξαγωγές απαιτούν έλεγχο. Meta box σε posts, όχι ακόμη σε custom post types. Οι νέες δημοσιεύσεις εμφανίζονται στον επόμενο κύκλο και οι διορθώσεις όταν παρέλθουν 5 δευτερόλεπτα από την τελευταία παρατηρημένη αλλαγή **στο συγκεκριμένο block**.

Καμία αυτόματη ενέργεια δεν πρέπει να πραγματοποιηθεί στα παραγωγικά pads πριν τη δοκιμή και τη ρητή σύνδεση από εξουσιοδοτημένο editor.
